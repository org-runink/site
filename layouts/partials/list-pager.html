{{/* Paging controls for the listing pages. Factored out of layouts/_default/list.html and layouts/taxonomy/list.html, which carried two near-identical copies differing only in whether the orange glow shadows were present. Both copies painted the current page number as a filled orange disc and every other one as a grey disc, which is a state carried by colour alone — so on paper, where tokens.css prints both fills white, a reader could not tell which page they were holding. The current page is now `aria-current` AND a darker rule AND the only one that is not a link, so the distinction survives monochrome. The context is the PAGINATOR, not the page: the layout has already initialised one over the pages it wants, and the second `.Paginate` call a partial like this would otherwise have to make is the documented way to get a build error. Call it as `{{ partial "list-pager.html" (.Paginate .Pages) }}` — the same arguments, so Hugo returns the cached paginator rather than building a second one. The whole nav is inside `.rk-list-screen`, which list-print.html hides — a printed page number is not clickable and the sheet reads as a fragment without an explanation, so paper gets the cards and nothing else. */}} {{ $paginator := . }} {{ if gt $paginator.TotalPages 1 }}

  1. {{ .PageNumber }}
    2. {{ else }}
  2. {{ .PageNumber }}
    3. {{ end }} {{ end }}
