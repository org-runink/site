{{/* --------------------------------------------------------------------- RUNINK — self-hosted faces. WHY THIS PARTIAL EXISTS. Hugo only writes an asset to public/ when something asks for it. A @font-face rule in a stylesheet is not asking: Hugo does not parse CSS looking for url(). So a face declared in tokens.css but never passed through resources.Get here is never published, 404s in production, and silently falls back to a system face — with no build error, no failed test and no visible break in a screenshot, because the faces that DO load are the ones that dominate the page. That exact failure already shipped once on the whitepapers, where four of six faces 404'd for months. THE RULE. assets/css/tokens.css declares eight @font-face rules. This file publishes eight. Adding a face to one means adding it to the other. The count is asserted below, so a mismatch fails the build rather than shipping. PUBLISH ALL, PRELOAD TWO. Preloading everything would compete with the stylesheet for the first connection. Only the two faces needed for first paint are preloaded: the reading face and the display face. --------------------------------------------------------------------- */}} {{/* Figtree first: it is the reading and display face for the marketing pages now, matching Runink FACE. Two variable files cover 300-900 in both styles, which is why this list did not grow by eight. Fira stays because the whitepapers are a document register that still uses it, and because Figtree has no monospace — standing marks and figures need Fira Code's fixed advance. */}} {{ $faces := slice "fonts/Figtree-var.woff2" "fonts/Figtree-Italic-var.woff2" "fonts/FiraSans-Book.woff2" "fonts/FiraSans-BookItalic.woff2" "fonts/FiraSans-Medium.woff2" "fonts/FiraSans-SemiBold.woff2" "fonts/FiraSansCondensed-SemiBold.woff2" "fonts/FiraSansCondensed-Heavy.woff2" "fonts/FiraCode-Regular.woff2" "fonts/FiraCode-Medium.woff2" }} {{/* Only the faces needed for first paint. Figtree upright is now the reading face on every marketing page, so it replaces Fira Book here; the condensed display face is preloaded only where it is still the display face, which is the whitepapers, and those publish their own. */}} {{ $preload := slice "fonts/Figtree-var.woff2" "fonts/FiraSansCondensed-Heavy.woff2" }} {{/* The count assertion this file's header promises. Until now the header claimed "the count is asserted below" and nothing asserted it -- there were only the per-file existence checks further down, which catch a face listed HERE with no file, but not a face declared in tokens.css and never listed here. That second direction is the one that actually shipped the whitepaper 404s, because it fails silently: the stylesheet asks for a URL Hugo never published. Counted off the src url() rather than the @font-face token, because the header comment in tokens.css contains the literal string "@font-face" and would inflate the count to nine. */}} {{ $tokens := resources.Get "css/tokens.css" }} {{ if not $tokens }} {{ errorf "rk-fonts: assets/css/tokens.css is missing -- it declares the faces this partial publishes." }} {{ end }} {{ $declared := len (findRE `url\('\.\./fonts/[^']+\.woff2'\)` $tokens.Content) }} {{ if ne $declared (len $faces) }} {{ errorf "rk-fonts: tokens.css declares %d @font-face src urls but this partial publishes %d. Add the face to BOTH or it 404s in production (see the header)." $declared (len $faces) }} {{ end }} {{/* Fail loudly rather than shipping a silent 404. */}} {{ range $faces }} {{ $f := resources.Get . }} {{ if not $f }} {{ errorf "rk-fonts: %q is declared in tokens.css but is not present under assets/. Every @font-face needs a file here or it 404s in production." . }} {{ end }} {{ $f.Publish }} {{ end }} {{ range $preload }} {{ with resources.Get . }} {{ end }} {{ end }}
