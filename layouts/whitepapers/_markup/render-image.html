WHY THIS EXISTS, AND WHY IT IS NOT A SHORTCODE ---------------------------------------------- markup.goldmark.renderer.unsafe is false, so raw HTML in a paper is stripped and an author cannot write inline SVG into the body. The usual escape is a shortcode, and a shortcode would have worked — but these four papers are kept in sync with print mirrors in ../pitch-decks, and the sync is a byte comparison of the body text. A shortcode call renders here and appears there as its own literal double-brace source, which puts a permanent, growing difference between the two copies. A markdown image has none of that problem. It is markdown, not Hugo: it survives the mirror unchanged, it still means something read as plain text, and any markdown converter pointed at the mirror renders the same picture. So the carrier is: ![long text alternative](figures/whitepapers/NAME.svg "Short caption") and this hook turns it into a figure. Body text stays byte-identical between the site source and the mirror, and the figures come with it. WHAT IT EMITS ------------- The SVG file is INLINED rather than referenced. That is the point of the whole arrangement: an is a separate document and cannot see this page's custom properties, so it could not re-ink itself when the print block re-points the .wp tokens, and would print as a light-grey smear on white. Inlined, the artwork reads --ink/--rule/--runs/--paper like everything else on the sheet and converts to black-on-white with the rest of the page. The files still carry literal fallbacks — var(--ink, #1c1917) — so the same file opened on its own, by whatever converts the mirror, is not colourless. ACCESSIBILITY ------------- The artwork is aria-hidden. It has no text inside it (at 360px the viewBox scales to about a third and any label set inside would be unreadable), so there is nothing in it for a screen reader to reach. The meaning is carried twice in HTML instead: the visible caption, and the markdown alt text as a full sentence in an accessible-only span.
